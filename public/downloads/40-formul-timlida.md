# 40 управленческих кейсов на собеседовании тимлида

Компактная шпаргалка по формулам ответа. Это рекомендации для подготовки, а не готовые ответы: связывай шаги со своим опытом и контекстом.

Больше материалов автора — [в Telegram-канале](https://t.me/+3fpriR795fY1MWEy).

1. **Срочная задача от бизнеса:** почему срочно? → что будет, если не сделать? → ценность → стоимость → что отложить? → решение.
2. **Как выбрать, какие задачи делать первыми**: ценность → срочность → стоимость → риски → зависимости → компромисс → решение.
3. **Бизнес требует «сделать прямо сейчас»:** последствия отказа → стоимость → влияние на текущий план → варианты выбора.
4. **Приоритеты постоянно меняются:** источник изменений → защитить команду от хаоса → единая очередь запросов → переоценка → явное перепланирование.
5. **Как пересмотреть план проекта при задержке**: отклонение → причина → новый прогноз → варианты → решение → коммуникация.
6. **Команда не выполнила работу в срок**: не искать виноватого → найти системную причину → восстановить план → изменить процесс.
7. **Требования к задаче неясны**: цель → пользователь → сценарии → границы → критерии готовности → оценка.
8. **После согласования задачи появляются новые требования**: исходный объём работы → новые требования → стоимость изменений → убрать / перенести / увеличить срок.
9. **Команде не хватает людей для всех задач**: приоритеты → объём работы → сроки → лишняя работа → только потом новые ресурсы.
10. **Как распределить время между техдолгом и новыми функциями**: риск → стоимость бездействия → стоимость исправления → влияние на план развития → баланс инвестиций.
11. **Разработчик не согласен с решением:** понять аргументы → отделить факты от предпочтений → варианты → решение → объяснение.
12. **Конфликт двух разработчиков:** разговоры 1:1 → факты → настоящая причина → общая цель → договорённость → проверка.
13. **Конфликт с продактом или аналитиком**: общая цель → интересы сторон → факты → варианты → последствия → решение.
14. **Как договориться о взаимодействии с требовательным коллегой**: мотивация → страхи → ожидания → формат взаимодействия → предсказуемость.
15. **Как убедить коллег в своём предложении**: понять возражения → общая цель → факты → последствия → конкретный следующий шаг.
16. **Нужно отказать бизнесу:** не просто «нет» → ограничение → стоимость → альтернативы → компромисс.
17. **Разработчик работает хуже ожиданий:** примеры → ожидания → причины → план улучшения → срок → проверка.
18. **Разработчик хочет перейти на следующий уровень**: ожидания → критерии уровня → чего не хватает до следующего уровня → план → задачи нужного масштаба → проверка.
19. **Разработчик потерял мотивацию:** 1:1 → причина → что можно изменить → автономия / рост / смысл → проверка.
20. **Как обсудить с сотрудником ошибки в его работе**: ситуация → поведение → последствие → ожидание → следующий шаг.
21. **Как реагировать на критику своей работы**: не защищаться → уточнить примеры → проверить понимание → решить, что менять → вернуться за фидбэком.
22. **Как принять и объяснить решение, которое не понравится команде**: данные → альтернативы → решение → объяснение → ответственность → последовательность.
23. **Нужно принять решение, но данных недостаточно**: какие данные нужны? → цена ожидания → минимально достаточная информация → обратимое решение → проверка.
24. **Как выбрать архитектуру системы**: требования → ограничения → варианты → плюсы/минусы → риски → обратимость → выбор.
25. **Спор об архитектуре:** критерии → убрать «мне нравится» → сравнить варианты → эксперимент → кто принимает решение.
26. **Как спланировать большой сложный проект**: цель → декомпозиция → зависимости → ответственные → контрольные точки → итерации.
27. **Как согласовать работу команд, которые зависят друг от друга**: карта зависимостей → ответственные → сроки → синхронизации → единый источник правды.
28. **Как организовать проект с участием разных специалистов**: цель → объём работы → ответственные → план → зависимости → коммуникация → запуск → ретро.
29. **Команда не понимает цели и планы работы**: цели → приоритеты → план развития → документация → регулярные обновления → вопросы.
30. **Как заслужить доверие команды**: выполнять обещания → быть предсказуемым → говорить о проблемах заранее → помогать → быть последовательным.
31. **Как разобраться в незнакомой технической области**: обзор → архитектура → собственная схема → вопросы экспертам → проверка понимания.
32. **Объяснить техническую проблему бизнесу:** что произошло → почему важно → влияние → варианты → рекомендация.
33. **Как объяснить сложную техническую тему**: цель → простой язык → аналогия → схема / пример → проверка понимания.
34. **Сбой в работающем сервисе**: стабилизировать → координатор → статус → восстановление → разбор инцидента → системное исправление.
35. **Сотрудник допустил серьёзную ошибку**: устранить последствия → не искать виноватого в моменте → найти системную причину → исправить процесс.
36. **Как сообщить руководству о ходе проекта**: план → факт → что изменилось → риски → что делаем → нужное решение / помощь.
37. **Как сообщить о задержке проекта и предложить варианты**: не скрывать → новый прогноз → причина → несколько вариантов → рекомендация.
38. **Проблему нельзя решить без участия руководителя**: попытаться решить самому → факты → влияние → что уже пробовали → какое решение нужно сверху.
39. **Как решить вопрос об увольнении сотрудника, который не справляется**: ясные ожидания → фидбэк → возможность исправиться → факты → решение → уважительный процесс.
40. **Как построить сильную команду**: люди → ожидания → автономия → фидбэк → рост → безопасность → ответственность.
